# StoneQR

Free, open-source (MIT), browser-only QR code generator. Brand: StoneQR at stoneqr.app. Tagline: "QR codes set in stone. Generated in your browser, never expire." Sibling of the private SignUpCity product; dynamic codes hand off to SignUpCity, StoneQR itself has no server, no accounts, no database.

## Rules

- Read `plan.md` first; it is the source of truth for scope, architecture, and milestones. Building started 2026-09-02. M1 to M8 are built, including halftone with zoom and crop, the bulk page, and the `?short=` return leg. Still open: the real-device scan matrix in `docs/scan-matrix.md` and the remaining M7 extras.
- The generator has Basic and Advanced control sets (toggle above the columns, remembered in localStorage). Anything only Advanced exposes must be listed in `Design.advancedInUse` so Basic can say it is still in force. Basic sizes are the four tiers in `apps/site/src/lib/generator/sizes.ts`; their reading-distance copy derives from `maxScanDistanceM`, so change the rule there, not the words. A hand-set width shows in Basic as a "Custom" row. The halftone feature is called "Photo QR" everywhere a user can read it (panel heading, notices, docs aimed at users); code, engine, and file names keep `halftone`. Basic includes Photo QR with upload, crop, and black-and-white; dot size, fade, and contrast are Advanced. Page heroes render inside the Generator's `hero` snippet; the heading shares a row with the Basic/Advanced toggle from `lg` up and stacks above it below that. Keep the row a breakpoint rule, never a flex-basis that happens to exceed phone widths: a hero given `flex-1` collapses to about 64 px next to the toggle on a 375 px screen. The landing pages (`/wifi`, `/vcard`, `/event`, `/logo`) are the same generator with a type preselected: the type picker is never locked, and one `Design` instance is shared across client-side navigations (module state in `Generator.svelte`), so a nav click only changes the type and keeps size, style, and typed fields. Nav links preload their code eagerly and the hero reveal animation runs only on the first load, so navigation must stay fetch-free and instant. The preview label and decode badge live in a caption strip at the bottom of the preview card so its top edge stays flush with the Content and Size cards.
- The call-to-action frame is our own SVG wrapper in `apps/site/src/lib/styled.ts`; do not reintroduce the styling library's border plugin (it sizes text as the whole code and needs a separate lazy chunk). Framed art is taller than wide: exports and the decode check go through the aspect-aware `svgToCanvas` and `Design.styledScale`.
- Halftone PNG export renders and encodes in `apps/site/src/lib/halftone.worker.ts`. Anything posted to it must be plain data (use `$state.snapshot` on reactive objects). Keep `renderHalftone` allocation-free in its inner loops; a 4096 px raster should stay around 200 ms.
- Commands from the root: `bun install`, `bun run dev`, `bun run test` (vitest: engine, then the site's pure modules), `bun run check` (svelte-check), `bun run build`, `./deploy.sh` (wrangler pages deploy). Bun uses isolated installs here, so packages live under `apps/site/node_modules` and `packages/engine/node_modules`, not the root.
- The engine's `index.ts` deliberately does not export the pdf-lib modules; import `@stoneqr/engine/export/pdf` and `@stoneqr/engine/labels` lazily from the site so the core chunk stays small (currently about 77 KB gzipped on the generator page, budget 150 KB).
- Golden files pin the hand-built renderers byte for byte: `packages/engine/test/golden/` (single-path SVG and EPS) and `apps/site/test/golden/` (the call-to-action frame). When a renderer change is intended, read the diff, then regenerate with `UPDATE_GOLDENS=1 bun run test`; never regenerate to make a red test go away.
- Open Graph cards are one PNG per route in `apps/site/static/og/`, drawn by `bun run og`: a Bun server plus a canvas page in `scripts/og/`, using the site's own fonts and the engine's matrices, so each card carries a scannable code to its own page. `/` keeps the hand-made `static/og.png`. A new route means an entry in `scripts/og/routes.mjs` and a `bun run og` run, which rewrites the generated `apps/site/src/lib/og-images.ts`; the site tests check the sitemap, the manifest, the files, and that every card still decodes.
- Claims about competitors or physics that appear on the site are tracked in `docs/claims.md`; verify before changing marketing copy.
- Nothing a user types may leave the browser in static mode. No server-side payload handling, ever.
- Every download must pass a decode check. Print safety is a feature, not polish.
- Stack: SvelteKit (Svelte 5) with adapter-static, TypeScript, bun workspaces, vitest; deploy as Cloudflare static assets with wrangler. Engine lives in `packages/engine` as `@stoneqr/engine`.
- Libraries: `uqr` for encoding, `@paulmillr/qr` for decoding with `jsqr` as a lazy fallback (the primary decoder misses about 1 valid symbol in 500), `@liquid-js/qr-code-styling` (lazy) for styled output, `pdf-lib` for PDF, hand-written EPS and pHYs. Do not add `sharp`, `node-canvas`, `jsdom`, or `@qr-platform/qr-code.js`.
- Research and sources: `docs/research/qr-technical.md`. Artistic QR techniques (halftone vs QArt bit steering vs diffusion), the library evaluation, and the unbuilt options live in `docs/research/artistic-qr.md`; nothing there is decided.
